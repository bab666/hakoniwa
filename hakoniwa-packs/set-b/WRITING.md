# 新婚部屋の文の書き方（担当向け）

設計は `docs/reports/2026-11-03/shinkon-design.md`。表のデータは `js/shinkon-data.js`（`HK.ShinkonData`）と `js/shinkon-r18-data.js`（`HK.ShinkonR18Data`）。
表の行は「何が起きたか」の種として内部で引くだけで、画面には出ない（2026-11-03 の作り直し）。担当が書くのは、その行を**一つの場面にした地の文**。
家事・料理をする文は、家事をしない設定の人が主語になると使われない（shinkon.js の choreOk）。台詞の話し手は kit-text.js（HK.PairKit。もとの shinkon-kit.js）が目印を付けるが、決めにくい文には「＠{a}＠」を直に書く。

## 1. 書式

- 表の行ごとに、同じ並び（番号）の配列に文を入れる：`T.DAILY = [ [文, 文], [文, 文], … ]`（`T.DAILY[i]` が `HK.ShinkonData.DAILY[i]` の地の文）。
- 1 行につき **2 本以上**（違う運び方で）。1 本は **2〜4 文**（短い場面の段落。長くしすぎない）。
- 名前は `{a}`・`{b}`（下の表のとおりの役）。ほかに使える印は各キーの欄に書いたものだけ。
- 台詞は **3 本のベース**：`「くだけた常体｜硬い常体｜敬語」`（同じでよいところは `＝`）。一人称は「私」、二人称は「あなた」（口調の辞書が話し手ごとに言い換える）。
  台詞の前に話し手が分かるように書く（「{a}は笑った。「…」」）。話し手が紛らわしいときは `「＠{a}＠…」`。
- 地の文は「{a}は〜した。」の過去形・三人称。性別の決めつけの語（彼・彼女・夫・妻・旦那）は使わず、名前で書く。
- 二人は**結婚したばかりの成人**。一緒に暮らしている（出張の日などは離れている）。
- 表の行の言葉をなぞるだけにしない。その行の出来事が起きた場面（何をして、どう感じたか）を書く。
- 表の行が「願望ptが高い方が〜」のように役を決めているときは、下の表の {a}／{b} の役どおりに書く。

## 3. R18 の文の決まり

- 形：**mf**＝{a} が男性（{b} の性別は問わない書き方）／**ff**＝女性どうし（指・舌・玩具。挿入の語を使わない）／**fm**＝{a} が女性・{b} が男性（{a} が跨る・主導する。女性に「押し入る・注ぎ込む」は書かない）。
- 体の語は**印**で書く：`{男性器}` `{女性器}` `{ナカ}` `{胸}` `{乳首}` `{精液}` `{尻}` など（一覧は `docs/reports/2026-10-26/lewd-words.md`）。
- 合意のある新婚の二人。暴力・合意のない展開・妊娠の描写は書かない。表の行に拘束・SM・首を絞める などがあれば、合意の上の軽い遊びとして書く（首は軽く手を添える程度で、すぐ緩める）。
- **攻めと受けを入れ替えない**（表の「主導権逆転」「能動が逆転」は、受けが積極的に求める・上に乗って甘える、までにする。{a} を受ける側に書かない）。
- PLAY は 3〜5 文の短い場面（きっかけ・事後は別の段が付く）。中くらいの場面では、共通の山場（喘ぎ・絶頂は態度ごと）が後ろに付くので、PLAY に絶頂の決着まで書かなくてよい。
- 表の言葉に体位・場所があればその通りに。玄関・車内など家の外に近い場所は、人に見られない書き方に。

## 4. 確かめ方（担当が自分で回す）

```
node hakoniwa-tools/build/pack-site.js hakoniwa-packs/set-b --out=<試しのフォルダ> --codes=<試しのコード>
```

- 組み立てが通ること（全年齢版のパックに性的な語が残ると止まる。両方のビルドに出るファイルに性的な語を書かない）。
- `node -e` で構文を確かめ、配列の数（52・10）が表と合うことを確かめる。
- できあがりの見本：`<試しのフォルダ>` の hakoniwa-full を開いてコードを入れ、新婚部屋を回して読む（まとめ役が回し方の道具を持っている）。
- 点検（audit-all・tone-feel・relcons・base-lint）はまとめ役がまとめて回す。

# 看病の部屋の文の書き方（担当向け。2026-11-03）

設計は `docs/reports/2026-11-03/kanbyo-design.md`。文は `js/kanbyo-text-a.js`・`kanbyo-text-b.js`・`kanbyo-text-c.js`（`HK.KanbyoText`）と、R18 は `js/kanbyo-r18-text.js`（`HK.KanbyoR18Text`。ファイル全体を r18 の印で挟む）。

- 役：ことわりの無い表は `{a}`＝看病する人、`{b}`＝看病される人（体調を崩した人）。看病し返す表（KAESHI・KMORN・KCARE・KNIGHT・KHEAL）は `{a}`＝看病し返す人、`{b}`＝うつって寝込んだ人。DATE・REI は `{a}`＝お礼をする人。CONFESS は `{a}`＝想いを告げる人。R18 の LEAD・FEEL・FANS は `{a}`＝言い出す人、PLAY・BOTTOM・TOP・OPEN は `{a}`＝攻め。
- 関係ごとの表は `{ 関係: [...], まとめ: [...], all: [...] }`。関係の鍵：spouse・lover・fam・pfam・ex・almost・crush（crushA＝看病する人が想う側／crushB）・bad・mentor（mentorA＝看病する人が師）・senpai（senpaiA＝看病する人が先輩）・work・childhood・friend・school・weak・none。まとめ：love・pine・close・work・fam・awk。関係の文を先に使い、使い切ったら all。
- 使える印：`{temp}`（その日の熱）、`{rel}`（関係の名前）、見舞いの表は `{g}`（来た人）・`{h}`（来た人と関係のある人）・`{gl}`（`{h}` から見た呼び名）。
- 一回の遊びで同じ文は二度出ないので、出番の多い表（看病の種・朝・夜・来る／帰る）は多めに書く（1 行の種につき 2 本以上、1 本 2〜4 文）。
- 恋愛の語（好き・甘え・抱き・キス・寄り添 など＝`HK.PairKit.ROM`）は、恋愛にならない二人では外れる。家族・不仲・同僚の表には書かない。「恋人」「付き合っている」は恋人どうしでない二人では外れる（「元恋人」は可）。結婚の語は夫婦の表だけ。
- 看病される人が出かける・家事をする・元気に動く文は、治った日より前の表に書かない。料理・家事の文の主語は看病する人（料理をしない設定の人には出ない）。
- 台詞は 3 本「くだけた常体｜硬い常体｜敬語」（一人称「私」・二人称「あなた」、敬語のベースに尊敬語・謙譲語を書かない）。名前が 2 人以上出る文は話し手の目印が自動で付くが、決めにくい文は `「＠{a}＠…」` を直に書く。
- R18：病み上がりの相手を気づかう合意の上の場面だけ。形 mf／ff／fm を書き分け、体の語は印、攻めを選んだ人を受けにしない。地の文は 3 文以上。
- 足したら：`node hakoniwa-tools/tone-check/base-lint.js hakoniwa-packs/set-b`、tone-feel（`--scen=set-b-kanbyo`。崩れは `kanbyo-tone.js` に書き下ろし）、出来事を足したら `kanbyo.js`／`kanbyo-r18.js` の `@event` と出来事の一覧。
- 目標（短期・長期）と結末の判定の一文は `js/kanbyo-text-e.js`（GOAL_S・GOAL_SR・GOAL_L・GOAL_LR・GOAL_RES・GOAL_LRES。目標の文は結末の段の中で「＠＠{goal}」の名詞の引用にする）。
- 追加の表（`js/kanbyo-text-d.js`）：家事で変わる出来事（CHORE_*・NOCHORE）、同居していない日（ALONE・ALONE_N・TEL・WEAK_TEL・ARRIVE_APART・LEAVE_APART・STAY_APART）、仲の悪い二人（FEUD_*・WEAK_ANS_FEUD・関係 rival・lovehate の導入）、病中の夜の翌朝（ILL_AFTER）。
  R18 の病中の夜は `kanbyo-r18-text.js` の ILL_*（理性が揺らぐ入口は、受けの「でも……」の段 ILL_HESIT を必ず書く）。
- 看病の部屋でしか出ない長い場面は `kanbyo-r18-text.js` の LONG_LEAD・LONG_OPEN（{ mf, ff, fm } × 2 本、2 段落）・LONG_AFTER。中盤と山場は本体の長い場面の部品が組み立てる。

# デートの日々の文の書き方（担当向け。2026-11-03）

## 行き先を足す・直す

`add({ id, name, label, size, cost, kind, trip, far, inn, sea, flags, spot, ev, tr, food })` で一か所。項目の意味は `date-places-a.js` の頭。

- `label` は出来事の一覧の表示名（8〜25 字。「遊園地でアトラクションをめぐる」の形）。行き先の表は `@event-table … rows=1` で一覧に出る。
- `size`：L（大型。一日一か所）／M（中。午前と午後で組む）／V（人や予算で長さが変わる）。泊まりの旅行は `trip: true` と `inn`（宿・ホテル・船室 など）、遠出は `far`（plane・shinkansen・rocket）。
- `sea`：行ける月（'7,8'）。季節の語（桜・花火・紅葉・雪・イルミネーション など）を書いた文は、その月だけに出る（date.js の SEA_RE）。季節のない行き先の文には季節の語を書かない。
- `flags`：kanran（観覧車がある＝山場の観覧車・やらしい雰囲気）／dark（暗がり）／view（景色）／night（夜の区切りに行く所）。
- 文の量：スポット 3 か所以上 × 2 本以上、出来事 4 種以上、トラブル 2 種以上、食事 2 種以上。1 本 2〜4 文。
- `{a}`＝その場面を引っ張る人、`{b}`＝相手（どちらが計画した人でもよい）。文ごとに役が入れ替わるので、「{a}の部屋」のような持ち主を決める書き方はしない（おうちデートは「部屋」とだけ書く）。
- 二人の関係を決めつけない（恋人・付き合っている・初対面・久しぶり などを書かない）。恋愛の語（手をつなぐ・キス・ときめく など＝date.js の DROM）は、恋愛にならない二人では外れる。「デート」の語は場面の文では使わず、使うなら `{date}`（恋愛にならない二人は「お出かけ」）。
- 料理・家事の文（台所に立つ・弁当を作る など）は、料理をしない設定の人が主語だと使われない。トラブルの文は困りごとだけを書く（受け止め方と決着は共通の部品が付ける）。
- 性的に読める語に注意（全年齢版の検査が止まる。例：カフェラテ→ラテ、竿→釣り竿）。

## 場面の文

- 表の役は各表の頭のコメントに書いた。関係ごとの表は `{ 関係の鍵, まとめ（love・pine・close・work・fam・awk・first）, all }`、態度ごとの表は態度 9 種。
- 台詞は 3 本「くだけた常体｜硬い常体｜敬語」（一人称「私」・二人称「あなた」、敬語のベースに尊敬語・謙譲語を書かない）。他の住人・三人目の台詞は `「＠{g}＠…」`・`「＠{c}＠…」` と話し手を書く。お店の人などモブの言葉は台詞にせず地の文で書く。
- 台詞の中に `{n}` などの数の印を入れない（口調の書き下ろしの鍵が合わなくなる）。
- 一回の遊びで同じ文は二度出さない（使い切ったらその段は出ない）。回数の多い段（待ち合わせ・計画・道中・夜の分かれ道）は多めに書く。
- 一緒に暮らしている二人には「家まで送る・{a}の家」の文、暮らしていない二人には「二人の家」の文が出ない（date.js の okText）。
- R18：きっかけ（LEAD）は地の文 3 文以上・体の組を問わない書き方。短い場面（PLAY）・反応（BOTTOM・TOP）・専用の長い場面（LONG）は mf／ff／fm を書き分け、体の語は印、攻めを選んだ人を受けにしない。
- 足したら：`node hakoniwa-tools/tone-check/base-lint.js hakoniwa-packs/set-b`、tone-feel（`--scen=set-b-date`。崩れは `date-tone.js`）、出来事を足したら date.js／date-r18.js の `@event` と出来事の一覧（`event-catalog.js --pack=hakoniwa-packs/set-b`・catalog-check）。

## 2 回目の直しで足した文（2026-11-04。設計は `date-design.md` の 9）

- 行き先の文の追加は `js/date-places-x1.js`〜`x12.js` の `HK.DatePlaces.more(id, { ev, tr, food, cl, rich })`（同じ名前の出来事には文を足し、新しい名前は種を足す）。今の量の目安：出来事 10 種（1 種 2 本以上）・トラブル 3 種・食事 3 種・山場 `cl` 1 か所以上・お金をかけたデート `rich` 2 種以上。
  - `cl`：最後のデートをこの行き先で過ごしたときの山場の始まり（{a}＝本音を言う人。場所と雰囲気の地の文 2〜3 文で、本音の台詞はあとに続くので書かない）。泊まりの行き先は夜の宿・帰ってきた夜でもよい（宇宙旅行の「帰還の夜」）。
  - `rich`：`[名前, 金額, [文]]`（{a}＝お金を出した人）。予算の残りで払える分だけ出る（10 万円の予算でも出るよう、安め 5〜20 万と高め 50 万〜を一つずつ）。夜の区切りに出るので、朝や昼を前提にした書き方をしない。
  - 体験型の行き先（`exp: true`。宇宙旅行・沖縄・オーロラ・グランピング）は、`spot` を「体験」として書く。順番のある体験は `ord: true`（表の順に出る。宇宙旅行は打ち上げが先）。
- 場面の文の追加は `js/date-text-d.js`（ときめき TOKI・お金をかけたデート RICH／RICH_RE／PRO_RICH・目標 GOAL_*・目標の本音 HONNE_G）と `js/date-text-e.js`（ダブルデート DBL_*・三人デート TRIO_*）。
  - ときめき：種ごとに関係の段階 4 つ（hajime 初対面・知人／tomo 友人など／kata 片想い／koi 恋人・夫婦）。{a}＝仕草をした人、{b}＝胸が高鳴った人。受け止め方 TOKI_RE は {a}＝胸が高鳴った人の態度 9 種。
  - 目標：`「目標の文＃種」`。種の意味は date.js の目標の節（GM_OK・GS_JUDGE）。目標の文は結果の画面にも「」付きで出るので、台詞にしない・人の名前を書かない。
  - ダブルデート：{a}{b}＝一組、{c}{d}＝もう一組（どちらの組が {a}{b} になるかは回ごとに入れ替わる）。台詞は必ず `「＠{c}＠…」` の形で話し手を書く。仲良し系とすれ違い系（張り合う・やきもち）を同じくらい。
  - 三人デート：{a}{b}＝デートの二人、{c}＝三人目。三角関係（tri）は {a}＝三人目の想う人。すれ違い系の種は TRIO_JEAL に名前を足す。
- R18 の三人の恋人の夜は `date-r18-text.js` の TRIO（きっかけ・形が決まったわけ・最中の段・事後）。直接の行為の語は本体の形の文（HK.Trio3）が書くので、TRIO の文には体の語を書かない。

# 配信の部屋の文の書き方（担当向け。2026-11-06）

設計は `docs/reports/2026-11-06/haishin-design.md`（担当の番号 P1〜P15・本数の目標は 15 章、表の名前は 16 章）。部屋の id は `set-b-haishin`、かたまりは `haishin`。
恋人か夫婦の二人が配信をする部屋で、記録は「本編（メインタブ）」と「コメント欄（コメントタブ）」に分かれる。**担当は自分のファイルだけを書き、ほかのファイル（kit-*.js・ほかの部屋・本体）は触らない。**

## 1. 二種類の文

| 種類 | 誰の言葉 | 書き方 | 口調の辞書 |
| --- | --- | --- | --- |
| 住人の文（地の文・台詞） | 配信する二人・画面の外の相手 | 地の文は過去形・三人称、台詞は 3 本 `「くだけた常体｜硬い常体｜敬語」`（`＝` は左と同じ） | 通る（tone-feel・base-lint の対象） |
| コメント（視聴者・モブ） | 画面の向こうの視聴者 | **1 本**。かぎかっこを付けない一行（`HK.HaishinCm` の表）か、メインの質問の `「＠…」`（話し手なし） | 通らない（口調を変えない・tone-feel の対象外） |

- 住人の台詞の一人称は `{一人称}`、二人称は `{二人称}`（`docs/reports/2026-11-06/fp-marker-design.md`。「私」「あなた」の直書きは古い書き方）。3 本で印の数が違ってよい（敬語では省くなど）。敬語のベースに尊敬語・謙譲語を書かない。
- 名前は `{a}`・`{b}`（表ごとの役は下の 3）。名前が 2 人以上出る文で話し手が紛らわしいときは `「＠{a}＠…」`。性別を決めつける語（彼・彼女・夫・妻・旦那）は地の文に書かず、名前で書く。
- 住人が視聴者に話しかける台詞は「みんな」「リスナーさん」と群れに呼びかける（一人の視聴者に `{二人称}` を当てない）。
- 台詞の中に数の印（`{v}`・`{yen}`）を入れない（地の文には書いてよい）。
- 関係の札の名前（両片想い・セフレ・元恋人 など）は、台詞にもコメントにも書かない（rel-word 0）。「恋人」「夫婦」をコメントに書くときは `{相方}` の印を使う。

## 2. コメントの書き方（P4・P5・P6）

- 一行一本。`'…'` の文字列か、体や役で絞るときは `{ t: '…', need: 'M'|'F'|'bot'|'top'|'solo'|'couple' }`（`M`＝呼ばれる配信者に男性器、`F`＝女性器、`bot`＝受けかリバ、`top`＝攻め）。体の語は R18 のファイルにだけ、印（`{男性器}`・`{胸}` など）で書く。
- 印：`{h}`＝そのコメントが呼ぶ配信者の配信の名前、`{h2}`＝カップルのもう一人、`{相方}`＝相手の呼び方（彼氏さん・彼女さん・旦那さん・奥さん・相方さん・パートナーさん。部屋が性別と関係で当てる）、`{ch}`＝チャンネル名。**住人の名前を直に書かない**（視聴者は配信の名前で呼ぶ。この部屋だけの例外。設計 14 章）。
- ハンドル名の表（`haishin-h`）は 150 本。実在の人物・団体・配信者の名前、商標を使わない。記号は「_」「・」と数字まで。
- 長さは 4〜30 字が中心。ネットの話し言葉（草・神・てぇてぇ・888・初見です）を混ぜてよいが、同じ言い回しの型（「〇〇すぎる」など）が一つの表に 3 本を越えないように散らす。
- 段ごとの温度：段 1〜3 は挨拶・感想・質問・冷やかし、段 4 は甘い冷やかし・せがみ、段 5・6 は熱い反応（R18 のファイル）。段 1〜3 の表に性的な語・ほのめかしを書かない（全年齢版の検査が止まる）。
- メインの質問・要求（`C.REQ`）は `{ t: 'コメント', k: '種類' }`。`k` は設計 4.3 の表の鍵だけ（新しい鍵を作らない。足したいときはまとめ役に言う）。段 2〜6 は `solo` と `couple` で別の文を 50 本ずつ（ソロは画面の外の相手のことを聞く・カップルは二人に聞く）。段 3 のカップルは `top`（攻め宛）・`bot`（受け宛）・`both` に分ける。
- カップルの段 4〜6 の要求は、**攻めが受けにする**か、**受けが攻めにする奉仕**（口で）だけを書く。攻めの体に入れる要求は書かない。段 6 の玩具を入れる要求は `need: 'bot'`。
- 後日談の SNS（`C.SNS[結末]`）は、配信を見た人の感想・切り抜きの話・二人の祝福。二人自身の投稿は住人の文（P3b）で書く。

## 5. 確かめ方（担当が自分で回す）

- `node hakoniwa-tools/check.js`（コミット済みなら `--since=main`）を終了コード 0 にする。パックのファイルを変えると、この部屋だけの点検（audit-all・tone-feel `--scen=set-b-haishin`・moan・rel-word・sex-flow など）が回る。目標：tone-feel 全口調 3% 以下（見ていない種でも 10% 以下）、base-lint・rel-word・catalog-check・sex-flow は 0 件、audit-all はすべて 0 件。
- 口調の崩れは `haishin-tone.js`（P13）に頼む（自分のファイルの台詞を 3 本で書き直して直るなら、自分で直す）。
- 出来事を足したら（P1・P8c・P11 など）、`/* @event … */` の印と表示名（8〜25 字）を付け、`node hakoniwa-tools/build/event-catalog.js --pack=hakoniwa-packs/set-b` で一覧を作り直し、catalog-check 0、差分を目で確かめて同じコミットに入れる。
- 自分の表を書いたら、試しのフォルダで 5 回以上回して、自分の文が出た記録を頭から読む（設定と食い違わないか・同じ文が続かないか・口調）。

## 6. 公開前の通し読み（P15b）で分かった、直すときの注意（2026-11-06）

計測の数字と通し読みの指摘は `docs/reports/2026-11-06/haishin-design.md` の 11.1 と `haishin-playtest.md`。

- **質問と答えは表の種類（`k`）で結ばれるだけ**：`C.REQ[段][形]` の一つの種類（`Q('media', …)` など）に入れた質問には、`T.ANS[段][種類][応え方]` のどの答えが返っても合う聞き方だけを書く。「どっちが〜？」「誰が決めるの？」「A と B どっち？」のような、答えの表が答えない形の質問を混ぜない（映画を聞いて音楽の答えが返っていた）。答えを足すときも、同じ種類の質問を全部読んで合うか確かめる。二人目の返し（`T.ANS2`）も、一人目のどの答えのあとにも合う文にする。
- **段 1〜3 の質問は一回の配信で同じ種類を二度聞かない**（haishin-cm.js の `main`）。答えどうしが食い違う種類（告白はどちらから・第一印象）があるため。
- **料理・ゲームの区切りの様子は順に引く**（haishin.js の `STEP_ORD`）。`T.STEP.cook`・`T.STEP.game` に種を足すときは `STEP_ORD` にも順の数を足す（無い種は 0＝いちばん先）。
- **寝落ち配信の朝の目覚め**：12・24 時間の配信は朝に `T.SLEEP.wakeMid`（配信を閉じない段）で起き、そのあとは `S.kindLive = 'zatsu'`（区切りの様子・設定の出来事・コメントの種類の表を雑談に）。`kind` の札（`kind: 'neochi'`）で書いた文は起きたあとには出ないので、朝にも合う寝落ちの文は札を付けない。最後の区切りの `T.SLEEP.wake` には配信を閉じる文を書いてよい。
- **時刻の語**：配信は朝・昼にも本番や配信の終わりがある（24 時間の配信）。「おやすみ」「夜が明けるまで」「今夜は」を書く文は、`tm`・`tz` の札で夜に絞るか、どの時刻でも読める言い方にする（`R.CUT`・`R.LEAKCUT` の「おやすみ」は haishin-r18.js が昼に外す）。
- **作れる人がいない料理配信の失敗の文**（`T.COOKFAIL.fail`）は、家事をしない人を主語にしない決まり（`K.choreOk`）を通さずに使う。ほかの表（`T.STEP.cook`・`T.SET` など）で料理をする文には `cook: 1` の札を付ける。
- **専用の長い場面の段（`HK.Play.addScene` の lead・steps）は kit の体の絞り込みを通らない**：mf の文は受けが男性のこともある（男×男）ので `{女性器}`・`{陰核}` を使わず `{ナカ}` で書く（haishin-r18-room.js の `fit` が女性器の語の文を外すが、全部の文に女性器の語があると外せない）。「配信はまだつけっぱなし」のくだりは、配信を切った回には `air` が外す決まりの言い方（「配信はまだ、つけっぱなしだった。」「配信はまだつけっぱなしで、」「モニターでは、配信の画面がまだ明るく光っていた。」）で書く。
- **ソロ配信のお仕置きのあとの文**：画面の外にいた人は配信に映っていない。書き出し（`MO.OPEN`・`MO.OPEN_SOFT`）と部屋の段に「配信中に〜」「配信のあいだ隣に〜」を書いたら、haishin-r18-room.js の `ROLE`（頭の語 → 'a'／'b'／'c'）に足す。お仕置きの短い場面（`PLAY[2]`）は、受けが配信していた回（攻めが焦らす）と攻めが配信していた回（受けが焦らす）の両方に合う文にする（「焦らされていた{b}」「玩具の代わりに」を書かない）。
- **結末の点数（haishin-end.js の `decide`）の係数を変えたら**、11 章の設定を各 20 回以上回して、結末 7 種の分かれ方を設計 11.1 に書き直す。長期目標「結婚の報告」はおまかせで選ばれやすいので、目標の点を上げると結婚報告に偏る。
- **渋りの確率（haishin.js の `stallP`）を変えたら**、11 章の 8（夜 30・12 時間）と 10（二人とも恥じらい）を各 40 回以上回して途中終了の回数を確かめる（目安 8 は 0〜3／20、10 は 3〜8／20）。
