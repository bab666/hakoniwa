# 口調の違和感の点検 tone-feel.js（2026-10-30 担当 TF）

利用者の決まり（CLAUDE.md）：「追加シーンがあったら 49 口調すべてチェックし、違和感を消してからプッシュする」。
口調直し第1〜5回で各担当が作業者の scratchpad に作った計測道具（台詞を集める `trace.js` と、口調ごとの判定 `check*.js`）を、リポジトリの点検道具 `hakoniwa-tools/tone-check/tone-feel.js` と判定の部品 `hakoniwa-tools/tone-check/feel/*.js` にまとめた。決まりそのもの（口調ごとの「自然な口語」）は `docs/reports/2026-10-30/tone-mixed-progress.md` の第1〜5回の節。

## 1. 使い方

```sh
node hakoniwa-tools/tone-check/tone-feel.js hakoniwa-full                    # 既定の一式（約 2 分）
node hakoniwa-tools/tone-check/tone-feel.js hakoniwa-full --scen=locker      # 場面を足した箱庭だけ（約 40 秒）
node hakoniwa-tools/tone-check/tone-feel.js hakoniwa-full --tones=kansai,hero --why   # 口調を絞り、違和感の台詞を頻度順に
node hakoniwa-tools/tone-check/tone-feel.js hakoniwa-zenrei                  # 全年齢版
node hakoniwa-tools/tone-check/tone-feel.js hakoniwa-full --mode=safe        # R18版の全年齢モード
node hakoniwa-tools/tone-check/tone-feel.js hakoniwa-full --base=hakoniwa-tools/tone-check/feel-base.json   # 基準と比べる
```

| 指定 | 既定 | 中身 |
|---|---|---|
| `<ビルド>` | hakoniwa-full | ビルドのフォルダ（名前に zenrei を含めば全年齢版として無印のページで開く） |
| `--scen=` | whiteroom,locker,omega | 回す箱庭（出られない部屋・媚薬ロッカー・オメガバース）。ほかの箱庭の id も使える |
| `--tones=` | 49 口調ぜんぶ | 口調を絞る（`HK.TONE_KEYS` の名前） |
| `--N=` | 24 | 箱庭ごと・種ごとの回数 |
| `--seeds=` | 2000,21001 | 種の始まり（1 回目は種＋回×7）。表では 1 つめを「見た」、残りを「見ていない」と書く |
| `--mode=` | r18 | R18版のページの hash（r18／safe）。全年齢版では無視 |
| `--why`（`--why=100`） | なし | 違和感の台詞を口調ごとに頻度順に（既定 30 件）。列は 本数・話し手の性別ごとの本数・当たった規則・台詞・出どころ・元の台詞 |
| `--json=` | なし | 結果の json（口調ごとの本数・割合・判定・種ごと・規則ごと・違和感の台詞の上位 40） |
| `--base=` | なし | 前の json と比べ、割合が 0.5 ポイント以上上がった・判定が下がった口調を出す |
| `--jobs=` | 2 | ページを何本並べるか（口調を本に配る） |

- 出力：口調ごとに「台詞（種類／本）・違和感（種類／本）・割合・種ごとの割合・判定・多い規則」の表。標準エラーに口調ごとの進み具合。
- 終了コード：**すべて ◯**で、シミュレーションの失敗・ページのエラーが無ければ 0。ほかは 1。
- 口調ごとにページを読み直す（前の口調の状態を持ち越さない）。結果は `--jobs` の本数・口調の並べ方によらない。

## 2. 台詞の集め方（第2〜5回の trace.js と同じ）

- ページは audit-all と同じ経路（`lib.js` の `openBuild`。分割読み込みの版は `#r18&all` で全部のかたまりを読む）。
- 住人：ハルカ（調べる口調。男女を 1 回ごとに交互・受け攻めを 2 回ごとに交互・恋愛対象は両方）、レン（相手。おまかせ）、ソラ（3 人目。媚薬ロッカーは毎回、ほかは 2 回に 1 回）。3 回に 1 回はハルカとレンが恋人。
- エゴグラム：口調を設定する 40 口調は 6 種（ふつう・厳格寄り・自由寄り・従順・やさしい・理屈）。**自動の態度口調 9 種**（強気・厳格・意地っ張り・穏やか・健気・冷静・奔放・恥じらい＝口調「おまかせ」で `HK.toneOf` がその口調を選ぶエゴグラムを決まった乱数で 8 種探す。丁寧 polite だけは口調を設定）は第3回 TD の作り方。頼れる兄貴・姉貴分（aniki）は口調を設定する側（TB の判定）。
- 環境：既定値。恋愛・夜・媚薬・発情・快楽などの上限があるものは上限。内容のスイッチは force 以外ぜんぶ（全年齢版はその版にあるスイッチだけ）。
- 数える台詞：記録の `e.seg` のうち、話し手がハルカの台詞行（l）・埋め込みの発話（e）。喘ぎ（♡・小さい母音を含む 14 字未満）は数えない。台詞ごとに話し手の性別を付ける。
- 出どころ（`--why` の［］）：OWN＝その口調の書き下ろし、BASE＝借りた書き下ろし（派生する口調の元）、D3＝3 本の台詞を辞書で言い換え、D1＝1 本の台詞の言い換え。元の台詞は 3 本（くだけた常体｜硬い常体｜敬語）か 1 本。

## 4. 合否の基準

- 口調ごとに、全部の種を合わせた割合（本数で加重）で **◯ 3% 以下／△ 10% 以下／✕ それより上**。
- **すべて ◯**（とシミュレーション・ページのエラー 0）で合格（終了コード 0）。CLAUDE.md の「全口調で違和感 3% 以下（見ていない種でも 10% 以下）」に当たる。
- 判定は機械の目安。「印なし」（12 字以上でその口調の印が一つもない）は、短い言い切りや静かな台詞でも当たるので、直すときは場面の意味・長さを変えない範囲で口調の語尾・口癖を足す（静かな台詞は「……」で間を置いてもよい）。

## 8. 基準の更新のしかた

1. 口調の辞書・書き下ろし・場面を直して build（両ビルド）。
2. `node hakoniwa-tools/tone-check/tone-feel.js hakoniwa-full --base=hakoniwa-tools/tone-check/feel-base.json` で悪化した口調がないことを確かめる（悪化した口調は `--tones=… --why` で台詞を見る）。
3. すべて ◯ なら `--json=hakoniwa-tools/tone-check/feel-base.json` で書き直して、直しと同じコミットに入れる（基準を下げる＝悪化を受け入れるときは、理由をこの文書かコミットに書く）。
4. 判定の規則を変えたときは、変える前と後の両方の数をこの文書に足す（`feel/*.js` の頭のコメントに何を変えたか）。

## 9. 新しい場面を足したときの手順

1. 場面・台詞を書く（台詞は 3 本 `「くだけた常体｜硬い常体｜敬語」`・一人称「私」・二人称「あなた」。R18 の文は印の中、体の語は印）。
2. 両ビルドで build（`node hakoniwa-tools/build/build.js hakoniwa-full`・`hakoniwa-zenrei`）。
3. `node hakoniwa-tools/tone-check/tone-feel.js hakoniwa-full --scen=<その箱庭> --why`（箱庭が既定の 3 つのどれかなら既定の一式でもよい。全年齢版にも出る場面なら `hakoniwa-zenrei` でも）。
4. ◯ でない口調・新しく出た違和感の台詞を、辞書（`js/tone-dict-builtin.js`）か書き下ろし（`tone-brush*.js` の形。両版の台詞は両ビルド、R18 の台詞は full の `*-r18.js`）で直して、2〜3 を繰り返す。
5. 全口調 ◯（終了コード 0）になったら、既定の一式を `--base=` 付きで回して悪化がないことを確かめ、ほかの点検（audit-all・base-lint・catalog-check など）と一緒にコミット・プッシュする。
