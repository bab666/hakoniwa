# スマホ版の不具合：グループの設定・PC とスマホの機能の差・画面が真っ白になる件（2026-11-04）

利用者の報告：

1. スマホ版でグループを設定する方法がない。「UI を変更してからこの手の不具合が多発している。PC 版より機能が少なくならないようにしてください」
2. スマホ版で箱庭の設定をしようとスクロールすると画面が真っ白になる（手元では再現しない）

画面を変えたら、下の「PC とスマホの機能の表」を更新し、スマホに無い機能を作らない（CLAUDE.md の決まり）。

## 1. グループはどこで設定するか

「グループ」は住人ごとの欄 `c.group`（読点・カンマ区切りで複数。40 字まで）。同じグループの住人は、

- 住人タブ：一覧をグループごとの節に分ける・「グループで絞り込む」の札・節の見出しの「仲間とみなす」「このグループを箱庭に入れる」「名前を変更」・並び「グループ順」
- 箱庭タブ：参加者の「グループで選ぶ」（このグループだけ／＋／−）・「グループ順に並べる」
- 住人の設定の窓：関係を「グループの全員と」付ける・話題の「グループ」の範囲

で使う。**グループを付ける欄は、住人の行の「＋グループ」（`input.grp`）しかなかった**。スマホ幅（599px 以下）の行は
`#view-cast .res .memo { display: none }`（index.html）でグループ・タグ・メモの欄ごと隠していて（同じ行の CP〜AC の数値の欄も隠していた）、
CSS の注記には「CP〜AC・グループ・メモは『設定』の窓と札で」とあったが、設定の窓にその節が無かった。2026-11-01 の画面の整え直し（担当UA、見本 03）で
行を 1 行の要約にしたときに抜けた。

**直し方**：住人の設定の窓に節「グループ・メモ」を足した（`js/ui-gear-basic.js`、late。PC でも同じ節が出る）。

- 名前・グループ（候補つきの欄＋今あるグループの札。押すと入る／外れる、複数可）・タグ・メモ・エゴグラムの数値（CP〜AC、0〜20）
- 開き方：住人の行の「›」（設定）→ 節「グループ・メモ」、または行の「⋯」→「グループ・メモ・エゴグラム」（その節を開いた状態で窓が出る）
- スマホの行の一行の要約の先頭に、付けたグループを札で出す（どのグループに入っているかが一覧で分かる）
- 保存先は行の欄と同じ（`c.name`・`c.group`・`c.tags`・`c.memo`・`c.eg`）。グループを変えたら話題の写し（`HK.TopicsUI.syncSave`）も行の欄と同じに更新

#### 追記（2026-11-04 午後）：住人の一覧でグループ・タグを選ぶ

利用者の指示「グループは住人の一覧にプルダウンを設けて、既定は『なし』、設定があれば選んだり新しく追加できる形に（一人ずつ設定を開くのは面倒）。スマホでも」
「タグも同じ考え方で」に合わせて、住人の行の自由入力の欄（`input.grp`・`input.tags`）を、選ぶ部品に置き換えた。

- **置き場所**：住人の行のいちばん下の段（名前のすぐ下。PC・タブレットは住人の列から右へ、スマホは行の幅いっぱい）。
  「グループ ▾」（選択の見た目。付いていなければ「なし」、付いていれば名前の札）と、タグの札（# 付き・× で外す）＋「＋タグ」（札＋「＋」の見た目）
- **操作**：押すと小さな一覧（PC は押した所の下、スマホは下から出る一覧）。今ある全グループ／全タグ（名簿の全員から集める・人数つき）にチェックで入る／外れる（いくつでも）、
  グループは「なし」で全部外す。「＋ 新しいグループ…」で名前を入れるとその人に付き、以後は一覧に出る。各名前の「⋯」で名前の変更・削除（全員から外す）。
  標準の `<select>` は使わない（Windows・Mac・iOS で見た目と操作を揃える）
- **まとめて付ける**：一覧の上（グループ・タグの絞り込みの下）の「まとめてグループ・タグを付ける」→ 行の左にチェック → 「グループに入れる ▾」「タグを付ける ▾」で同じ一覧
  （選んだ全員が持っていれば ✓、一部なら −。押すと全員に付く／全員から外れる）→「終わる」。PC・タブレットは上に止まる帯、スマホは下の帯（「取り込み」「＋住人を追加」の帯と入れ替わる）
- **設定の窓**の節「グループ・メモ」のグループ・タグも同じ部品（`HK.TagSel.field`）。二重に実装していない
- 実装：描くのは中核の `js/ui-tagsel.js`（`HK.TagSel`。br 約 2.7KB）、押したあとの一覧・まとめて付ける操作は late の `js/ui-tagsel-pop.js`（`HK.TagSelPop`）。
  グループの名前の変更は `HK.CastTools.renameTo`（隠す・仲間・ランダムの元・折りたたみ・話題も一緒に移す。見出しの「名前を変更」と同じ処理）
- **データの形は変えていない**：`c.group`（読点区切り・40 字まで）・`c.tags`（同・80 字まで）。超える人には付けずに知らせる。書き出し・読み込み・セーブはそのまま
- 確かめたこと（Playwright。390×844 iPhone の UA・768×1024 タッチ・1280×900）：横のはみ出し 0、スマホ・タブレットで押す所はすべて 40px 以上（PC はマウス向けに 28px）、
  新しいグループを作る・タグを付ける・まとめて 3 人に付ける・名前を変える・設定の窓から外す、がそれぞれ `c.group`・`c.tags` に入ること。
  スクリーンショットは作業用フォルダの `group/`（`before-*`・`after-<幅>-1list`〜`9gear-pop`）

## 3. 画面が真っ白になる件

### 調べたこと（手元の Chromium。WebKit はこの環境に入れられなかった）

`white.js`（作業用）で、iPhone 相当（390×844・iOS の Safari の UA）・Android（360×800）・横向き（844×390）× R18 版（19 箱庭）と全年齢版（16 箱庭）の
全箱庭を選び、箱庭タブの設定を下まで速くスクロール・ランダムな位置へ飛ぶ・止まる目次を押して節へ移る・「変える」の窓の開け閉め・住人の設定の窓の開け閉め・
タブの切替・戻るボタン、を繰り返し、`pageerror`・`console.error`・画面の中の見える要素の割合（`elementFromPoint` で 30% 未満を「白い」とみなす）を見た。
→ **例外 0 件・白い画面 0 件**（直す前も後も）。切り欠きの余白（`env(safe-area-inset-top)` = 47px）は Chromium では 0 になるので試せていない。

再現しない以上、「真っ白」になりうる作りを洗って、WebKit（iPhone・iPad・Mac の Safari）でだけ違う動きをするものを潰した：

| 候補 | 中身 | 判断・対処 |
|---|---|---|
| **content-visibility** | 箱庭タブを隠しているあいだ `#view-box[hidden]{display:block!important;content-visibility:hidden}`（ui-box-draw.js、レイアウトを捨てないため）、住人の行・関係の行に `content-visibility:auto` | Safari が対応したのは 18（2024年9月）から。それより前の iOS と Chrome では効かない／正しく動くので「手元では再現しない」と合う。WebKit では省略していた箇所が、表示に戻したりスクロールしたりしても描かれず白いまま残ることがある。**最有力**。WebKit では使わないようにした（`ui-guard.js`：html に `hk-webkit`） |
| 表の描き直し | 参加表の縮尺（ui-perzoom.js）が `resize` のたびに表を当て直していた。iOS はスクロールでアドレスバーが出入りするたびに `resize` が来る | スクロール中に上に止まる列のある大きな表の CSS を何度も計算し直していた。**幅が変わったときだけ**当て直し、変わらない属性は書かないようにした |
| 小窓の背景の固定 | HK.Modal は窓を開くと body を `position:fixed` で止める | 窓が無いのに止まったままだと、スクロールしても動かない・ずれた位置のまま。スクロールが止まったとき・ページに戻ったとき（`pageshow`・`visibilitychange`）に `HK.Modal.sync` で戻すようにした |
| 描画の例外 | タブの描き直しで例外が出ると、タブの中身が空のまま残る | 下の「保険」で、空になったら描き直す |
| LATE_READY 前の描画・かたまりの読み込み失敗 | 失敗は `#loadfail` の帯で知らせ、画面は消さない作り | 変更なし。読み込めなかったかたまりは記録に残す |
| sticky と will-change・backdrop-filter | `will-change`・`backdrop-filter`・`translateZ` は使っていない | 該当なし |
| 100vh／dvh と fixed | 高さはどれも `100dvh`（無ければ `100vh`）基準で、中身を画面外に押し出す組み合わせは無かった | 該当なし |
| メモリ | 中核は br 856KB（R18 版）。iOS で落ちるとページごと白くなる | 中核はほぼ増やしていない（+4KB）。落ちたかどうかは記録の「画面」「位置」で次に分かるようにした |

### 入れた保険（`js/ui-guard.js`・中核、`js/ui-guard-view.js`・late）

- **不具合の記録**：画面で起きた例外（`error`・`unhandledrejection`）・読み込めなかった本体のかたまり（`js/` の下）・画面が空になったことを、時刻・タブ・箱庭・画面の大きさ・
  スクロール位置・版と一緒に、このブラウザに 40 件まで残す（localStorage の `hakoniwa-errlog`）。右上の「表示」のメニューの「不具合の記録（n件）」で見る・コピーする・消す。
  コピーした文にはブラウザ（UA）・画面・倍率・WebKit かどうかが付く。住人の名前や設定は入らない
- **空の画面の見張り**：例外のあと・スクロールが止まったとき・ページに戻ったときに、いま見ているタブ（住人・箱庭・結果）の中身が空・高さ 0 になっていないかを見る。
  空なら一度だけ描き直し（`HK.UI.refresh`）、それでも空なら真ん中に「画面をうまく表示できませんでした」の板（もう一度表示する／読み込み直す／不具合の記録をコピー）
- **例外の知らせ**：このページのファイルで例外が出たら、画面の下に「もう一度表示する／記録をコピー／×」の小さな知らせ（15 秒で消える）。拡張機能・外のウィジェットの例外は記録だけ

確かめたこと：例外を投げる・結果タブの中身を消す、を Playwright で試し、記録に残ること・描き直しで中身が戻ること・メニューから記録を開いてコピーできることを見た。

次に報告があったときは、「表示」→「不具合の記録」をコピーして送ってもらう（WebKit かどうか、どのタブ・箱庭・位置で何が起きたかが分かる）。
