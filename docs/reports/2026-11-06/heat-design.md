# 温度 6 段（HK.Heat）の設計（2026-11-06）

利用者の指示（2026-11-06）：
- 「新しい部屋（新婚・看病・デート・同居生活・痴漢電車）から温度を読む」
- 既存の箱庭は従来の夜の色（`HK.EroFlavor` 4 段）のままにして結果を変えない（check.js の regress＝結果の指紋の一致で確かめる）
- 点検に「温度の矛盾」を足す（0 件で合格）

仕様は CLAUDE.md の「温度 6 段（`HK.Heat`）」。どのエッチも「二人が今どういう関係で、どんな気分か」で温度が決まり、きっかけ・エッチの型・台詞・事後が同じ温度を読む。

## 1. 6 段と夜の色（`HK.EroFlavor`）との対応

| 温度（鍵） | 表示 | いつ | 夜の色（`HK.Heat.flavor`） |
|---|---|---|---|
| fresh | 初々しい | 初めて・片想いの成就・恥じらいが高い | sweet（甘め）※新しい段 |
| sweet | 甘い | 恋人・喜び | sweet（甘め） |
| play | じゃれ合い | 幼馴染・バディ・セフレで仲が良い | deal（駆け引き） |
| dry | ドライ | 割り切り・条件・モブ | dry（ドライ） |
| rough | 荒い | 怒り・嫌心・火照りが強い・嫉妬 | rough（荒め）。受けが攻めを選んだ組（`HK.Pos.hardTop`）は deal |
| warped | 歪んだ | 執着・支配・共依存・合意のない場面 | rough（荒め）※新しい段。受けが攻めを選んだ組は deal |

夜の色の 4 段 → 温度：甘め→甘い、ドライ→ドライ、駆け引き→じゃれ合い、荒め→荒い。初々しい・歪んだは温度にだけある段。
**既存の箱庭では 6 段を使わない**：温度は部屋が `HK.Heat.use(scenId)` で登録したときだけ働く（`HK.Heat.enabled(scenId)`）。登録したのは同居生活（futari）・電車（train）・新婚（set-b-shinkon）・看病（set-b-kanbyo）・デート（set-b-date）の 5 部屋だけ。ほかの箱庭の夜は今までどおり `HK.EroFlavor.of` が色を決める。

## 2. 決め方（`HK.Heat.of(ctx, a, b, opt)` → `{ key, base, shifted, why, force, forceOk }`）

乱数を使わない（本筋の乱数の流れを変えない）。a＝攻め・b＝受け。

1. **土台（関係の種類と段階）**：
   - 相手がモブ（乗客）→ ドライ。電車の乗客の性格の色（`opt.flavor`）があれば、甘め→初々しい（おずおずした乗客）、駆け引き→じゃれ合い、荒め→荒い
   - 執着（`yan`）・支配（`abuse`）・信仰の支配（`worship` の dominate）・恐怖が和らいでいない二人（`HK.fearHeld`）・執着度 60 以上（`HK.Obsess.level`）→ 歪んだ
   - 敵対・不仲（`enemy`・`bad`）→ 荒い
   - 恋人・夫婦・番・運命・両片想い・片想いの成就・血縁（夜まで来た二人）→ 初めてなら初々しい、二度目以降は甘い
   - 幼馴染・バディ・親友・友人・同級生・双子 → 初めてなら初々しい、二度目以降はじゃれ合い
   - セフレ・体だけ（`opt.rel` が casual）→ お互いの好意（低いほう）が 50 以上ならじゃれ合い、ほかはドライ
   - 元恋人・ライバル → じゃれ合い（駆け引き）、同僚・上司・先輩・師弟・主従 → ドライ
   - どれでもない → 初めてなら初々しい、ほかはドライ
   - 「初めて」は `opt.first`（部屋が知っていれば）か、この回の二人の温度の記録（`HK.Heat.last`）が無く `ctx.pair(a,b).nights` も 0 のとき
2. **ずらし（いちばん高い気分で一段）**：二人の `c.emo`（`HK.Emo`）のうち 35 以上でいちばん高いもの
   - 仲直りの夜（部屋の `opt.kind === 'naka'`）→ 甘い（怒りが残っていても仲直りの直後は甘い）
   - 嫉妬の夜（`opt.kind === 'jeal'`）→ 荒い
   - 怒り 50 以上 か 火照り 85 以上 → 荒い（歪んだはそのまま）
   - 恥じらい → 甘い・じゃれ合いは初々しい、ドライはじゃれ合い
   - 喜び → ドライはじゃれ合い、じゃれ合いは甘い、荒いはじゃれ合い（初々しいはそのまま）
3. **合意のない場面**：温度は合意のない入口を新しく作らない。`opt.force`（部屋がもう合意のない場面として組んでいる）なら `force: true`、`forceOk` は内容のスイッチ `HK.Content.on(env, 'force', 部屋)` の判定のまま。電車（合意なし寄りの部屋）は、荒い・歪んだになっても内容のスイッチ「無理矢理」が切ならドライに戻す（`HK.Heat.use('train', { forceGate: true })`）。

`why` は記録の理由書きに「温度：甘い（恋人・二度目／喜び）」のように足す。

## 3. 温度が決めるもの

| 決めるもの | どこで | 中身 |
|---|---|---|
| きっかけの文の系統 | `HK.Heat.lead(ctx, h, a, b)` | 温度ごとの一文（各 3 本）をきっかけの段に足す（同居生活）。札 `HK.Heat.LEAD_TAG`（初々しい＝ためらい・甘い＝名前を呼ぶ・じゃれ合い＝からかい・ドライ＝言葉のいらない・荒い＝収まらない熱・歪んだ＝離さない） |
| 入り方・責め・道具・体位・終わり方の重み | `HK.Play.choose`（温度の場面のあいだ `HK.Heat.cur` を読む。表 `HK.Heat.PLAY`） | 甘い→キスから×3・全身にキス×2（押し倒す・嫉妬・押さえつけ・言葉責め・目隠しは 0）／荒い→押し倒す×3・我慢できずに×2・押さえつけ×2／初々しい→キスから×2・焦らし×2.5（服の上から＝着衣×2）・正常位×2（押し倒す・我慢できずに・押さえつけ・言葉責め・目隠し・玩具・続けて何度もは 0）／じゃれ合い→甘えて（受けが誘う）×3・騎乗位×2／ドライ→我慢できずに×3・キス×0.5・全身にキス 0／歪んだ→言葉責め×3・目隠し×3・押さえつけ×3 |
| 前戯の長さ | 部屋の組み立て | 初々しい・甘い→前戯の段を二つ（同居生活の寝室の夜・新婚／看病／デートの部屋の段）、ドライ→一つ |
| 台詞の甘さ | 夜の色（`HK.Heat.flavor` を `opt.flavor` で長い場面に渡す） | 夜の色の仕組み（`HK.EroFlavor`）が、ドライ・駆け引き・荒めのとき攻めの台詞・喘ぎの甘い切れ端を外す |
| 事後の型 | `HK.Heat.after(ctx, h, mode, opt)` | 温度 × 3 組（mf・ff・fm）× 3 文（初々しい＝顔を隠す・照れて笑う／甘い＝腕枕・額にキス／じゃれ合い＝からかい合う・くすぐる／ドライ＝背を向ける・黙って服を着る／荒い＝息を荒げて離れる・残った痕／歪んだ＝離さない・指を絡めて縛る）。車内（`spot: 'car'`）は温度ごとの車内の 3 文 |
| 二度目以降の変化の一文 | `HK.Heat.change(ctx, h, a, b)` | 前回の温度（`HK.Heat.last`）と違うときだけ、今の温度ごとの 3 本から（「前の夜はどこか素っ気なかったのに、今夜の{a}は…」）。同じ二人で同じ文は 1 回まで |
| 場面のあとの気分 | `HK.Heat.move(ctx, h, a, b)` | 温度ごとに気分を動かす（甘い→喜び、初々しい→喜び＋恥じらい、荒い→怒りが引く、ドライ→火照りが引く、歪んだ→受けに恐れと恥じらい）。関係の値は今までどおり部屋が動かす（新婚・看病・デートの `mod2`、同居生活の夜の出来事） |

前回の温度は `HK.Heat.remember(ctx, a, b, key)`／`HK.Heat.last(ctx, a, b)`（その回の ctx に二人ごと。モブとは覚えない）。保存済みの記録は書き換えない（新しい記録の理由書きに温度を書くだけ）。

## 5. エッチの決め事の残り（段 2.5。温度を読む部屋とこれから作る部屋だけ）

CLAUDE.md の「エッチの決め事」のうち未実装だったもの。既存の箱庭の結果は変えない（regress 一致）ので、(b)(c) は `HK.Play.strict(scenId)`（＝`HK.Heat.enabled(scenId)`）が真の部屋だけで効く。

- (a) **部屋だけの新しい値の口** `HK.Play.addValue(scenId, axis, { key, label, weight, text, mid, short })`：その部屋の `P.choose` にだけ候補として入る（`P.ROOM` の重み）。文は本体の表 `HK.PlayText` の同じ形（入り方 ENTRY・主な責め FOCUS＋FOCUS_MID＋SHORT_FOCUS・道具 PROP の {fore, mid}・体位 POS＋POS_MID＋SHORT_POS・終わり方 FIN）に足す。3 組 × 3 文に足りない値は `HK.Play.VALUE_ERR` に名前が残る（点検が数える）。口を足すだけなので、どの箱庭の結果も変わらない。
- (b) **飽きない決まり**：同じ組（攻め・受けの名前）の前の夜と同じ入り方・主な責めは選ばない（今までの ×0.25 を 0 に。ほかに候補が無いときだけ残す。受けからの夜の主導 lead は数えない）。道具（無し以外）は一回の遊びに同じものを 2 回まで（`memo().propN`）。
- (c) **体格差・体の特徴の文を「主語にせず動作の中に溶かす」**：温度の場面のあいだ（`HK.Heat.cur`）だけ、`HK.Attr.featLines`・`pairLine` が溶かした文の表（`HK.Heat.MELT`：特徴 10 種 × 3 本・体格差 大／小 × 3 本。主語は人か手・指で、特徴は動作の目的語か連体修飾に入る）を使い、一回のエッチに 2 文まで（3 文目からは書かない）。連続させない決まり（`A.featPick`）はそのまま。
- (d) **きっかけ → 場面 → 事後の一言の着地と、場面のあとに必ず動く気分**：同居生活は きっかけの段（温度の一文）→ 場面 → 事後の型の一文、新婚・看病・デートは部屋のきっかけの段 → 場面 → 事後の型の一文 → 部屋の `mod2`、電車は きっかけの段 → 場面 → 事後の型の一文 → 住人の数値（快楽・かかり具合）。どの部屋も `HK.Heat.move` で気分を動かす。

## 6. 点検「温度の矛盾」（`hakoniwa-tools/tone-check/heat-audit.js`）

使い方：`HK_PACK_CODES=<コード> node hakoniwa-tools/tone-check/heat-audit.js <試しのフォルダ>/hakoniwa-full [--scen=futari,train,…] [--N=20] [--seeds=1,2] [--why]`（check.js が試しのフォルダ pack-site で回す）。
温度を読む 5 部屋を「恋人どうし・エッチ多め」ほかの設定で回し、温度の場面の記録（`HK.Heat.log`：温度・気分・型・事後の型・変化の一文・本文）を照らして数える。合格は 0 件。

| 種 | 判定 |
|---|---|
| (a) 甘い・初々しいに荒い入り方 | 型の入り方が押し倒す・嫉妬、主な責めが言葉責め、体位が押さえつけ、道具が目隠し、または本文の入り方・事後の段に「押し倒・組み敷・縛・拘束・手首を押さえ」 |
| (b) 荒い・歪んだ・ドライに甘い事後 | 事後の型の一文・本文の最後の 2 段落に「腕枕・額にキス／口づけ・髪を撫で」 |
| (c) 怒りが高いのに甘い事後 | 記録の気分（二人の怒りの高いほう）が 50 以上なのに、温度が甘い・初々しい、または事後に (b) の語 |
| (d) 歪んだの合意のない場面を内容のスイッチが許していない | `force` なのに `forceOk` が偽 |
| (e) 変化の一文の誤り | 前回と同じ温度（か前回が無い）のに変化の一文が出た |
| (f) 同じ二人で同じ変化の一文が 2 回以上 | |
| (g) 同じ組で同じ入り方・主な責めが続いた | 段 2.5 の (b)。lead は数えない |
| (h) 道具が一回の遊びに 3 回以上 | 段 2.5 の (b) |
| (i) 体格差・体の特徴の文が一回のエッチに 3 文以上・特徴が主語の文 | 段 2.5 の (c)。温度の場面で出た特徴の文（`HK.Heat.cur.feat`）が溶かした文の表にない・3 文以上 |
| (j) 部屋だけの新しい値の文が足りない | `HK.Play.VALUE_ERR` |
