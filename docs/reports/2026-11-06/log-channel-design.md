# 記録の欄 `e.ch`（コメント欄）の設計（2026-11-06）

追加パックの配信の部屋の「視聴者のコメント」を、本編の記録と分けて読ませるための本体の仕組み。記録の中に置き（話者推定・体の語の印の解決・名前の塗りを全部通る）、欄 `e.ch` で分ける。

## 1. 書き方（パック）

```js
var e = ctx.say({ kind: 'phase', cat: 'phase', actors: [], text: '「＠＠こんばんは」\n「＠＠待ってた」', mag: 0, lewd: false });
if (e && !e.skipped) e.ch = 'cm';
```

一区切り一件・改行で並べる（配信の部屋の切り忘れの本番の区切りだけは、本編の段の合間に差すため 3 件。haishin-design.md の 1 章の 13）。`actors: []`・`lewd: false`（恋愛・夜・状態の点検と数えから外れる）。体の語は画面の住人の体に合わせる。モブは住人の名前を呼ばない（`hakoniwa-packs/README.md`）。

## 2. 画面（view.js）

| 所 | 中身 |
| --- | --- |
| 絞り込みの状態 | `tl.ch`（'side'＝並べる／'main'＝e.ch の無い記録／'cm'）。新しい結果（`rvFresh`・`V.resetFilter`）で覚えた見え方（既定は side）。記録に無い欄なら side、欄の無い記録はいつも main |

## 3. 保存・点検

- セーブ・履歴は結果の JSON をそのまま置くので、欄が一つ増えるだけ（保存後に書き換えない決まりに触れない）。JSON の書き出し（ui-json.js）にも残る。共有の札は結末だけなので影響なし。
- `e.ch` を持つ記録は本体の箱庭には無いので、本体の結果は変わらない（regress 一致）。
- 古い本体（`HK.Packs.API` 2 以下）ではコメントが本編に混ざって見え、表情の鍵の印が画面に出るので、`API` を 3 に上げ、セット B の `api` も 3 にした（古い本体では「本体を新しくしてください」）。

## 4. 確かめ（Playwright・幅 1280 と 390（isMobile・hasTouch））

同居生活の結果の JSON に、区切りごとのコメント欄の行（`ch:'cm'`）を 6 件足して `HK.UIres.show` で開いた：

- 本編：コメントの行 0 件、「経過 78件」はコメントを数えない、切り替えに「コメント欄（6件）」
- コメント欄：6 件だけ、区切りの見出しつき、横のはみ出し無し（幅 1280・390）
- テキストの書き出しの本編にコメントが無く、後ろに「■ コメント欄」、印刷の間だけコメント欄 6 件が足され、印刷のあとで消える
- 吹き出し・カードの台詞に `data-face`

## 5. 並べる見え方（2026-11-06 の 2 回目。利用者の指示「タブを切り替えないと表示できなくて読みづらい。同時に見られるようにしてほしい」）

切り替えを「並べる（既定）｜本編だけ｜コメント欄だけ（n件）」の 3 択にし、並べるときは本編とコメント欄を同じ区切りの中で同時に見せる。選んだ見え方はブラウザに残す（`localStorage` の `hakoniwa:rv` の `chv`。新しい結果・開き直しでもそのまま）。記録・保存・履歴は変えない。確かめは `log-channel-side.md`。

| 所 | 中身 |
| --- | --- |
| `tlGroups`（side） | 欄の記録は絞り込みを当てずに区切りの `g.cm` に、本編は今までどおり絞り込む。絞り込み中は本編が残った区切りだけ出し（その区切りのコメントは全部）、コメントだけの区切りは絞り込んでいないときだけ出す。`g.n`（区切りの件数）・目次の件数・重要の印は本編だけ |
| 区切りの中身（`blkBody`） | `.chsp`（左 `.chm` 本編・右 `.chc` コメント欄）。日ごとの区切り（`scen.stepGroup`）は日の中の中見出しごと。右の列の頭に「コメント欄 n件」（n はコメントの行の数） |
| コメントの行（`chatBody`） | 1 行 1 コメント。「名前［額］：本文」の名前と額を薄く（`.cmh`・額は `.cmy`）、本文はいつもの名前の塗り。本編だけ・コメント欄だけ・並べるのどれでも同じ |
