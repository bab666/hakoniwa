# 追加パックの土台（2026-11-02）

新しい箱庭のセット（有料の追加パック）を、本体とは別に作り直して配れるようにする仕組み。
仕様書（「新規箱庭セット 仕様書」のアクセスコードの節）の「サイト公開版」「データ配布版」の両方を、同じ仕組みで動かす。

## 0. 要点

- 追加パックは **`<ビルド>/packs/<枠>/pack.js`** の1ファイル。枠は `set-a`〜`set-l` の決まった名前（12枠）。
- 中身（箱庭のかたまりと目録）は **コードで暗号化** してある。コードを入れると本体の目録に足され、ほかの箱庭と同じく「選んだときに読む」。
- **本体とパックは別々に作り直せる。** パックは本体の「かたまりの名前」（`pack-rel`・`scen-futari` など）にだけ頼り、ファイルの中身の hash には頼らない。本体を作り直してもパックはそのまま動く。パックを作り直すと鍵は変わるが、端末に覚えたコードで自動で開き直す。
- **サイト公開版**：`packs/index.js`（置いてある枠の一覧）を読み、そこにある枠だけを読む。「箱庭を追加」のボタンは、まだ開けていないパックがあれば出る。
- **データ配布版**：`packs/index.js` を入れない。本体は12枠を全部読みに行き、読めた（フォルダを置いた）ものだけを使う。フォルダが無ければボタンもコードの入力も出ない。
- 入れたコードは端末に覚える（`localStorage` の `hakoniwa-packs`。全年齢版は版ごとの鍵）。書き出し（portable.js）には入れない。
- セーブ・履歴の記録は書き換えない。開けていない箱庭の結果を開くと「この画面にありません（コードを入れると開けます）」と出すだけ。

## 2. 暗号の形

- コードを整える：NFKC（全角→半角）→ 大文字 → 空白・`-`・`_`・長音記号を除く。整えたあと6文字以上。
- 中身の鍵 K（32バイト・乱数）を、コードごとに PBKDF2-HMAC-SHA256（塩16バイト・10000回）で作った鍵で ChaCha20 で包み、HMAC-SHA256 の先頭16バイトで確かめる。コードが違えば合わない。
- 1つのパックに、そのセットのコードと「まとめ用」のコード（`codes.local.json` の `"*"`）の両方の枠を入れる。まとめ用のコードを1回入れると、置いてある全部のパックが開く。
- 中身（JSON）は K で ChaCha20。改ざん・取り違えは HMAC で見る。
- 端末には、パックごとに「整えたコード・パックの印（m）・K」を覚える。パックが同じなら K でそのまま開き（計算なし）、作り直されていたら覚えたコードで開き直す。
- 計算の時間（Node・実測）：鍵の計算 1回 約20ms、2MB の中身を開く 約170ms。
- 守れるのは「ファイルを直接読んでも中身が出ない」まで。コードそのものが共有されれば開く（500円の商品として、この割り切りで十分という判断。購入者ごとのコードにするにはサーバーが要る）。

## 3. 版の合わせ方

| 状態 | どうなるか |
| --- | --- |
| パックの `api` が本体の `HK.Packs.API`（今は1）より新しい | 「本体が古いため開けません。本体を新しくしてください」 |
| パックが頼る本体のかたまりが、本体の目録に無い | 同上（本体の分け方が変わったとき） |
| パックの `api` が `HK.Packs.MIN_API` より古い | 「追加データが古いため開けません。追加データを新しくしてください」 |
| R18版のパックを全年齢版に置いた（逆も） | 「別の版（R18版と全年齢版）の追加データです」 |

- 本体の中の仕組みを、パックの書き方が変わるほど変えたら `HK.Packs.API` を上げ、古いパックを受けないなら `MIN_API` も上げる。
- R18版の全年齢モード（#safe）では、本体と同じ取り付け役（safe.js）がパックの箱庭にも当たる（肩見出しに R18 のある箱庭は出ない）。
  箱庭が全部 R18 のパック（build-pack.js が pack.js の表に `r18only` を付ける。Cセットなど）は、全年齢モードでは「箱庭を追加」の画面にも出さない。

## 4. パックの書き方

`hakoniwa-packs/README.md` に詳しく。要点：

- `pack.json` に id・枠・名前・紹介・ビルド・かたまり（ファイルと、頼る本体のかたまり）を書く。頼るかたまりはビルドで違ってよい（`{ "full": [...], "zenrei": [...] }`）。
- 箱庭の id はパックの id で始める（`set-a-tentacle` など）。登録は `HK.SCENARIOS[id] = 箱庭;` だけ（並びは本体が足す）。
- ファイルは本体と同じく、最上位を `(function () { … })();` で包む。両方のビルドに出すファイルの R18 の文は `/* r18:begin */`〜`/* r18:end */` で挟む（全年齢版のパックを作るときに落とし、性的な語が残っていれば止まる）。
- パックのファイルは本体の後ろの通し番号で包む（1000000＋枠×10000＋並び）。`HK.wrap`・`HK.addTo` を使っても本体の後ろに並ぶ。

## 5. 作り方と配り方

```
# 本体（いつもどおり）
node hakoniwa-tools/build/build.js hakoniwa-full
node hakoniwa-tools/build/build.js hakoniwa-zenrei
# パック（本体を build したあと。本体の目録とかたまりを vm で読んで、パックの箱庭の目録を作る）
node hakoniwa-tools/build/build-pack.js hakoniwa-packs/set-a            # pack.json の builds 全部
node hakoniwa-tools/build/build-pack.js hakoniwa-packs/set-a --dist     # 配布用の zip も（dist/hakoniwa-full-set-a.zip）
# データ配布版の本体の zip（packs は空。置き方の説明だけ）
node hakoniwa-tools/build/build-dist.js hakoniwa-full
```

- サイト公開版：`<ビルド>/packs/` ごとアップロードする（`pack.js` と `index.js`）。`.htaccess`・`_headers` で `packs/` は毎回たしかめる（名前が変わらないため）。
- データ配布版：本体の zip（無料）と、セットごとの zip（`packs/<枠>/pack.js` と説明）を配る。まとめ買いは4つの zip とまとめ用のコード。
- 本体だけを直したとき：本体を build してアップロードするだけ（パックは作り直さなくてよい）。パックが頼るかたまりの名前を変えたときだけ、パックも作り直す。
- パックだけを直したとき：`build-pack.js` で作り直して `packs/` をアップロードするだけ。

## 6. 確かめたこと（2026-11-02）

- 暗号：SHA-256・HMAC・PBKDF2・ChaCha20・base64 が node の crypto と一致（長さ 0〜100000 バイト）。
- 画面（Playwright・Chromium。見本のパックを試しのフォルダに組み立てて）：
  - サイト公開版（http）の R18版・全年齢版、データ配布版（file://）のフォルダあり：「箱庭を追加」が出る／開ける前は部屋が一覧に無い／入力画面にセットの名前だけ／違うコードは「コードが違います」／正しいコード（全角・小文字・- の有無を混ぜても）で部屋が加わる／全部開けたらボタンが消える／部屋が動く・結果の画面が出る／読み込み直してもコードを聞かない／ページのエラーなし。
  - データ配布版のフォルダなし：ボタンが出ない・エラーなし。
  - パックだけ作り直す → 覚えたコードで自動で開く。本体より新しいパック → 開かずに「本体が古い」と出る。開けていない箱庭のセーブ → 「この画面にありません」。
  - build-dist.js の zip を解凍した本体：パックなしでボタンなし → パックの zip を解凍して入れると開ける。
- 本体の結果が変わらないこと：regress.js の指紋が変更前と一致（R18版 19箱庭・全年齢モード 14・全年齢版 16）。chunk-audit.js 0件（両版）。

## 7. main への取り込み（2026-11-03）

- main（箱庭を選ぶ窓・PC の上の一覧・吹き出しなどの画面の整え直し）を取り込んだ。中核を小さく保つ決まり（2026-11-01）に合わせ、`pack-crypto.js`・`packs.js`・`packs-ui.js` は late に移した（画面が出たあとで読み、パックが届いたら一覧を描き直す。中核の増減なし）。
- 「箱庭を追加」は窓の一覧の最後と、PC の上の一覧の最後の両方に出す。
- 確かめ：regress の指紋が取り込む前の main と一致（R18版 19・全年齢モード 14・全年齢版 16）、chunk-audit・chunk-regress・catalog-check 0件、audit-all すべて 0 件、画面の試し（サイトの R18版・全年齢版・スマホ幅、配布版のフォルダあり・なし）すべて OK。
- 知っていること：前に選んでいた箱庭がパックの箱庭だと、読み込み直した直後（パックが開く前）は一覧の最初の箱庭が選ばれる（パックが開いたあとで選び直す）。
