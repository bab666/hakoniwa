# 口調チェック（箱庭シミュレーター）

台詞の口調の整合性を、実際にシミュレーションを回して調べるための道具です。
Playwright（Chromium）でビルドのページを開き、全箱庭を何度も実行して、住人の台詞を
「元の文・変換後・口調・文脈」つきで集めます。

## 口調の違和感の点検（場面・台詞を足したら毎回）

`node tone-feel.js ../../hakoniwa-full [--scen=locker] [--tones=kansai] [--why] [--base=feel-base.json]`：49 口調 × 3 箱庭で台詞を集め、口調ごとの決まり（feel/*.js）で違和感の割合を出す。すべて ◯（3% 以下）で終了コード 0。約 2 分。詳しくは docs/reports/2026-10-30/tone-feel.md。

## 使い方

```sh
cd hakoniwa-tools/tone-check
# 1. 台詞を集める（R18版は最後に r18。seeds を増やすほど正確）
node collect.js ../../hakoniwa-full out-full.json 40 r18
node collect.js ../../hakoniwa-zenrei out-zen.json 40

# 2. 口調ごとの成績（元のまま残る割合・書き下ろしの割合・「……」だけの割合・敬語とため口が混ざる割合）
node report.js out-full.json out-zen.json
#    ※「元のまま」が問題になるのは、台詞の表を借りている口調（古風な紳士・のじゃ・関西弁・無口・敬語・敬語まじりなど）。
#      ツンデレ・穏やかなど、表がもともとその口調で書かれている口調では、元のままで正常
#    ※「敬語とため口が混ざる」は、敬語まじりのため口で上がっていればよい指標（文ごとの語尾で判定）
#    ※「うちため口の文末がはっきりある」は同じ数え方を細かくしたもの。「〜ですわ」「〜なさい」「〜まーす」も敬語に数え、
#      体言止め・呼びかけ・あいさつ・「〜ので」の言いさしはどちらにも数えない。敬語の口調ではこちらが低いほどよい
#      （敬語の口調の、ため口の文末を敬語に寄せる仕上げは js/tone-keigo-unify.js）。MIX2=1（または口調名）で該当の台詞を標準エラーに出す

# 3. 口調に合わない語尾・一人称のずれ
node lint.js out-full.json            # 全口調
node lint.js out-full.json kansai 20  # 関西弁だけ、各20件

# 4. 書き下ろしの作業リスト（まだ書き下ろしのない台詞を、出現回数の多い順に）
node worklist.js noja 200 out-full.json out-zen.json > work-noja.txt

# 5. 長い台詞順の作業リスト（長い台詞ほど言い換えの継ぎ目が目立つので、上から整える）
node longest.js genki 100 out-full.json out-zen.json > long-genki.tsv   # 長さ・回数・箱庭・元の台詞・変換後
```

Playwright が見つからないときは `npm i -D playwright` するか、`PLAYWRIGHT_MODULE` にモジュールのパスを、
`CHROMIUM_PATH` にブラウザのパスを指定してください。

`HOT=1` を付けると、過激さ・媚薬などの設定を最大にして集める（抵抗・喘ぎの台詞を点検したいとき）。
`SEED0=30` のように付けると、乱数の種を30番目から始める（前回と別の回で追加点検したいとき）。
`lint.js` は、はっきりした口調（強気・兄貴分・厳格・冷静・意地っ張り（中性的）・紳士・のじゃ）に
「離して」「見ないで」「やだぁ」「〜のよ」のような弱々しい拒み・女性的な語尾が残っていないかも拾う（言い換えは js/tone-firm.js）。

`TONE=gentleman` を付けると全員の口調を固定でき、`FPS=俺,あたし,自分` を付けると一人称を順に設定できます。

## 口調を足すとき

口調の一覧は `js/tone-registry.js`（HK.TONES）の一か所にまとまっている。名前・説明・一人称・選択欄の並び・
借りる文面の表・設定画面の見本・場面ごとの分類（敬語／やわらかい／強い）・渋りやすさは、すべてここから読む。

1. `tone-registry.js` の TONES に一つ足す（書く順が選択欄の並び）。
2. 既存の口調の台詞を作ってから語尾だけ替える口調なら `derive: 'polite'` のように派生元を書き、
   語尾の付け替えを `HK.toneFinish('口調', 関数)` で登録する（例：`tone-polite-kin.js` の後輩・お嬢様）。
   その口調名で `tone-fix.js` に登録した直しは、付け替えずにそのまま使われる。
3. まったく新しい言い換えが要る口調は、`tone-extra2.js` などと同じく `V.styleQuote` を包んで書く。
4. 両方のビルドに同じファイルを置く。ここの道具は `HK.TONE_KEYS` を読むので、新しい口調もそのまま点検される。

## 書き下ろし辞書の育て方

- 辞書は `js/voice-override.js`（古風な紳士・決まり文句の表）と `js/voice-override-rows.js`（のじゃ・関西弁・無口・敬語、
  敬語まじりのため口は同じファイルの MIXED）。
  両方のビルドに同じファイルを置く。
- 元の台詞の住人の名前は `〈〉` にして書く。一人称は「私」で書けば、その人の一人称にそろう。
- 優先するのは **出現回数が多い台詞 × 自動変換で元のまま残る台詞 × 元の口調から遠い口調**。
  上位200〜300行で、プレイヤーが目にする台詞の約半分になる。
- 書き足したら `collect.js` → `report.js` で、「元のまま」の割合が下がったかを確かめる。


### 今後の方針（2026-10-25）
- 口調ごとの辞書（ギャル・チャラい・ヤンキーなど）は今ある分を残す。新しく足すときは、口調ごとに同じ元の文を何度も書き下ろすのではなく、「元の文 → 言い換え」の共通の辞書として書き、語尾の味付けは口調の仕上げ規則（HK.TONE_FINISH・tone-keigo-unify）に任せる。
- 新しい口調は、できるだけ既存の口調からの派生（derive）＋仕上げ規則で作る（専用の辞書を持たない）。

## 新しく台詞を書くときの決まり

- 語尾は中立に（「〜だ」「〜ない」「〜した」）。「〜じゃん」「〜だよね」「〜わよ」のような口癖は、
  自動変換が外しきれないので、元の文にはなるべく入れない。
- 一人称は「私」、二人称は名前か「あなた」で書く。
- 長い台詞は、読点で区切った短い文の連なりにする（文末だけ変換されても読めるように）。

## audit-all.js（点検の一式。2026-10-29）

```
node audit-all.js                         # 既定の一式：R18版・全年齢モード・全年齢版（ページを 2 本並べて約 4 分）
node audit-all.js --modes=r18             # モードを絞る（r18,safe,zen）
node audit-all.js --extra=group           # 追加の配役パスも（sexgate・feud・group・state-hot・name、all で全部）
node audit-all.js --only-extra --extra=sexgate,feud
node audit-all.js --print=out             # 今までの道具の形の出力を、パスごとに out/<道具>-<モード>.txt に書く
node audit-all.js --cross                 # 判定をほかのパスの回にも当てる（調べもの用。誤判定を含む）
```

モードごとにページを 1〜2 枚だけ開き、パス（今までの各道具の配役・seed・環境値の決め方。回数も今までの既定どおり）を順に回して、
判定（orient・pos・state・loveflag・seg・qa と、取り込んだ文の崩れ misc）を当てる。各道具の判定は、その道具のファイルの関数
（`module.exports` の passes・judges）をそのまま使うので、件数は道具の単独実行と同じになる。最後に 1 枚のまとめ（判定ごとに
「すべて 0 件」か、0 でない項目と例）を出し、0 でない項目・シミュレーションの失敗・ページのエラー・判定の例外があれば終了コード 1。
qa（問いと返事）・group・feud・sexgate は比率の点検なので、参考の数として出す（feud・sexgate は目安に届かない箱庭があれば 1）。

| 既定の一式に入るパス | R18版 | 全年齢モード | 全年齢版 |
|---|---|---|---|
| orient（40 回） | ○ | ○ | ○ |
| pos・pos-hot・pos-ffhot（24 回ずつ） | ○ | | |
| state（24 回＋追加の配役） | ○ | ○ | ○ |
| loveflag（24 回） | ○ | ○ | ○ |
| seg（10 回） | ○ | ○ | ○ |
| qa（12 回） | ○ | | ○ |

追加の配役パス（`--extra`）：sexgate（R18版・約 3 分）、feud・group（R18版・全年齢版）、state-hot（state を `--hot` で）、name（名前の双子の回）。
単独の道具（`node orient-audit.js …` など）も今までどおり使える（中身は audit-all と同じ関数）。設計と所要時間は `docs/reports/2026-10-29/audit-consolidation.md`。
setting-audit.js（設定ごとの効き目の表）・moan-audit.js（口調・夜の性格・喘ぎの設定を一つずつ固定して回す）は、回し方が既定の一式と違い、表を読む道具なので audit-all には入れず、R18 の設定・喘ぎを変えたときに単独で回す。

## setting-audit.js（性行為に関わる設定が場面に反映されているかの点検。2026-10-27）

R18 の性行為に関わる設定（住人の⚙設定「恋愛と夜」「体と設定」「相手ごとの設定」、全体の設定、箱庭の R18 の環境値）を一つずつ
「分かる値」にして全箱庭を各 N 回回し、性的な記録（e.lewd）の本文・理由（e.why）・点検用の記録（夜の性格の文 HK.Attr.log、
夜の主導の文 HK.PosLead.log、体の特徴の文 HK.Attr.raceLog／featLog、受け攻めの向き HK.Pos.order、喘ぎの呼び出し HK.Attr.moanLog）から、
その設定が効いた回を数える。対象の住人は 0 番（アキラ）、相手は 1 番（ミナト）。

```sh
node setting-audit.js ../../hakoniwa-full 6                       # 全設定×全箱庭の表（3分ほど）
node setting-audit.js ../../hakoniwa-full 8 room,omega --probe=night --why   # 箱庭と設定を絞る。--why で効いていない回の例
node setting-audit.js ../../hakoniwa-full 1 --probe=body.genM --dump=island#3  # その回の性的な記録の全文
node setting-audit.js ../../hakoniwa-full --list                  # 設定の一覧
```

- 表のマス：dir（効いている回／効くはずの回。「(なし x/y)」は設定なしで同じ印が出た回）・excl（設定なしで起きた場面が、設定ありで 0 になった回）・
  rate（設定あり：なし の数。◯ は期待どおりの向き）・cnt（件数の割合）。◯ は 8 割以上、△ は 2 割以上、✕ はそれ未満、－ はその箱庭で起きない
- 性器（男性器・両方・ふたなり・女性器）は語か挿入の書き方で見る。小説調には体の語を書かない文も多いので、出ない回は「食い違い」ではない（食い違いは pos-audit の V7・V8）
- 体の語の印は、性器の呼び方を見る設定だけふつうの列、ほかは「直接」の列で語にする

```

node state-audit.js ../../hakoniwa-full 24 safe --why
node state-audit.js ../../hakoniwa-zenrei 24 '' --why
```

出来事の記録（`HK.Ctx.prototype.say`・`HK.Story.say`）を包み、記録された瞬間の住人の状態を見て数える。

| 印 | 数えるもの |
|---|---|
| S1 | 前の区切りより前に死んだ人が、出来事の主語になった（結末・弔い・遺体の発見・ゾンビ化した住人は除く） |
| S2 | 監禁中の人が、執着の出来事（cageOk）以外の記録に残った |

| S4 | 「R18に参加しない」人が性的な文に名前つきで出た（R18 版だけ） |
| S5 | 「恋愛・R18にしない相手」の二人だけが、同じ性的な文に出た |
| S6 | 「恋人だけ（モブにも襲われない）」の人が、住人でない相手との性的な文に出た |
| S7 | 一つの記録の中で同じ性的な文が二度出た |
| S8 | 内容のスイッチで切った出来事（`tags`）が出た |
| S9 | 吹雪の館で、助手が自分の探偵ではない探偵を「先生」と呼んだ |
| S25 | 死んだ人（同じ区切りの中の死も）が、記録の文で主語・話し手（`名前「`・seg の who）・性的な文として出た（弔い・回想・遺体・名前を呼ぶ・関係節・ゾンビ化・事件と推理の札などは、除外の辞書 `DZ` で外す） |
| S26 | 死んだ人が出来事の主役になった／文に名前の出ない登場人物として残った |
| S27 | 遺体の残らない死（穴・塵・呑み込まれた・引きずられていった など。engine.js の `HK.State.noBody`）の人に、亡骸・抱きしめる・手を握る文が出た |
| S28 | 亡くなった人が、蘇り・治療・ループなどの記録なしに生きている状態に戻った |
| S29 | 結末・行く末・その後・結末の文で、亡くなった人が生きている扱い（生還・恋人として暮らす・主な関係に（死別）がない など）／生きている人が亡くなった扱い |
| S30 | 場を離れた人・閉じ込められた人（物語型の縛られた人・囚われを含む）が、主役・話し手として出た |

S25〜S30 は、記録ごとに書く直前の住人の状態を写して文で見る。ふつうの回に加えて、死のある箱庭を不死・吸血鬼（不死あり／なし）・同一人物・執着・愛憎・発狂しやすい気質・展開と死ネタの重さ「重い」で回す追加の回（N/2、4 回以上）でも数える。死・退場・蘇りに触れる変更のあとは、3 通り（24 回と 60 回、素と `--hot`）で S1〜S3・S25〜S30 が 0 件であることを確かめる。

項目ごとの除外（正規表現・札・出来事の除外）の棚卸しは `docs/reports/2026-10-29/audit-consolidation.md` の「state-audit の例外」。

「止めた」は `Ctx.say` の防波堤で捨てた件数（出所を直すと減る。0 でなくてよい）。恋愛・夜・状態に触れる変更のあとは、3 通りとも S1〜S9 が 0 件であることを確かめる。

## dict-regress.js（口調の辞書の成績。2026-10-25 試作）

```
node dict-regress.js ../../hakoniwa-full kohai,ojou,noja,kansai,gyaru --show=5
```

口調の辞書（`js/tone-engine.js`・`js/tone-dict-builtin.js`）の出力を、書き下ろし辞書（`tone-fix*.js` の「元の台詞 → その口調の台詞」）と比べる。
完全一致・文末一致（最後の文の末尾3文字）と、残りの差分の種類（文末だけ・語彙・組み替え）を口調ごとに出す。
元の台詞は1本（くだけ／硬め／敬語のどれで書かれているか分からない）なので控えめな見積もり。台詞の3本化が進むほど上がる。
「組み替え」が2割を超える口調は、辞書では届かない台詞が多い目安（ベースを足すか、行単位の上書きに残す）。
3本（「K｜F｜P」）で書かれた台詞は、その口調のベースから作って比べ、「└3本」の行に分けて出す。こちらが辞書の本当の成績で、辞書を直すときはこの行の実例（--show）を見る。

## 3本のベースで台詞を書く（試作）

`「くだけた常体｜硬い常体｜敬語」` と全角の縦棒で区切って書くと、話し手の口調に合うものを選んでから口調の辞書で言い換える
（`js/tone-engine.js`。「＝」は左と同じ）。1本の台詞はこれまでの言い換えのまま。
決まり：一人称は「私」、二人称は「あなた」、名前は `{b}`。文末は K が 〜だよ／〜だね／〜かな／〜の／〜て、F が 〜だ／〜か／〜な／〜だろう／命令形／〜てくれ、P が 〜です／〜ます／〜ください。
いまは `js/mini-serifu.js`・events-common・daily-kit・drunk・epilogue・scenario-rpg・scenario-omega・rpg-data・zombie-events・incidents-social・incidents-extra・goukon-talk の台詞が3本。`collect.js` の「元の文」は、選ばれたあとのベースが入る。

## base-lint.js（3本の台詞の約束の番人）

```
node base-lint.js ../../hakoniwa-full          # 問題のある行だけ
node base-lint.js ../../hakoniwa-full --all    # 全部の行
```

「K｜F｜P」で書いた台詞を全部集め、3本そろっているか、印（{a} {b} 〈〉 など）が一致しているか、P の最後の文に敬語の形があるか、
K・F の文末に敬語が残っていないか、F の文末がくだけていないか（だよ・だね・じゃん・でしょ・かな・の？）、一人称が「私」・二人称が「あなた」か、を確かめる。
わざと敬語の決まり文句（K と P が同じ）と、「〜て」「〜けど」の言いさしは許す。3本の台詞を足したら、コミットの前に回して問題 0 にする。

## name-audit.js（住人の名前が言い換えで壊れていないかの点検。2026-10-28）

```
node name-audit.js ../../hakoniwa-full 6 r18      # --why で例を多く、--no-probe で台詞の見本を省く
node name-audit.js ../../hakoniwa-full 6 safe
node name-audit.js ../../hakoniwa-zenrei 6
```

言い換えの語を名前に含む住人（飯塚・飯沼・飯塚太郎・飯・飯田！・酒井・金子・腹巻・胸元・君島・私市・兄上・本当・剛直・快楽 など約40人）を順に配役し、全口調で全箱庭を回す。
同じ種で名前だけを言い換えに当たらない字（柊・椿…）にした「双子」の回も回し、双子の名前を戻した文と記録ごとに比べて、名前に触れる違いを数える
（接頭辞＝「ご飯塚」「お腹巻」、一部＝名前の字が別の語になった・名前がまるごと別の語になった・結果の住人の名前が変わった）。
あわせて「台詞の見本」（全口調 × 全名前 × 文の型を台詞の仕上げ全部 HK.Voice.processResult に通す）も同じく比べ、名前の伏せ字（U+9FA6〜U+9FFE・U+E100〜U+E1FF）が結果に残っていないかも数える。
名前に触れない違い（くじの違い・段落ごと別の文）は参考に出すだけ。名前・呼び名を言い換えから守る仕組みは voice.js の `HK.NameGuard`（台詞の言い換えの入口で伏せ、出口で戻す）。
台詞の言い換え・地の文の言い換えを足したら回して 0 件にする。
