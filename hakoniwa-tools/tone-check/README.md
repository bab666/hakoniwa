# 口調チェック（箱庭シミュレーター）

台詞の口調の整合性を、実際にシミュレーションを回して調べるための道具です。
Playwright（Chromium）でビルドのページを開き、全箱庭を何度も実行して、住人の台詞を
「元の文・変換後・口調・文脈」つきで集めます。

## 使い方

```sh
cd hakoniwa-tools/tone-check
# 1. 台詞を集める（R18版は最後に r18。seeds を増やすほど正確）
node collect.js ../../hakoniwa-full out-full.json 40 r18
node collect.js ../../hakoniwa-zenrei out-zen.json 40

# 2. 口調ごとの成績（元のまま残る割合・書き下ろしの割合・「……」だけの割合・敬語とため口が混ざる割合）
node report.js out-full.json out-zen.json
#    ※「元のまま」が問題になるのは、台詞の表を借りている口調（古風な紳士・のじゃ・関西弁・無口・敬語・敬語まじりなど）。
#      ツンデレ・穏やかなど、表がもともとその口調で書かれている口調では、元のままで正常
#    ※「敬語とため口が混ざる」は、敬語まじりのため口で上がっていればよい指標（文ごとの語尾で判定）

# 3. 口調に合わない語尾・一人称のずれ
node lint.js out-full.json            # 全口調
node lint.js out-full.json kansai 20  # 関西弁だけ、各20件

# 4. 書き下ろしの作業リスト（まだ書き下ろしのない台詞を、出現回数の多い順に）
node worklist.js noja 200 out-full.json out-zen.json > work-noja.txt

# 5. 長い台詞順の作業リスト（長い台詞ほど言い換えの継ぎ目が目立つので、上から整える）
node longest.js genki 100 out-full.json out-zen.json > long-genki.tsv   # 長さ・回数・箱庭・元の台詞・変換後
```

Playwright が見つからないときは `npm i -D playwright` するか、`PLAYWRIGHT_MODULE` にモジュールのパスを、
`CHROMIUM_PATH` にブラウザのパスを指定してください。

`HOT=1` を付けると、過激さ・媚薬などの設定を最大にして集める（抵抗・喘ぎの台詞を点検したいとき）。
`SEED0=30` のように付けると、乱数の種を30番目から始める（前回と別の回で追加点検したいとき）。
`lint.js` は、はっきりした口調（強気・兄貴分・厳格・冷静・意地っ張り（中性的）・紳士・のじゃ）に
「離して」「見ないで」「やだぁ」「〜のよ」のような弱々しい拒み・女性的な語尾が残っていないかも拾う（言い換えは js/tone-firm.js）。

`TONE=gentleman` を付けると全員の口調を固定でき、`FPS=俺,あたし,自分` を付けると一人称を順に設定できます。

## 口調を足すとき

口調の一覧は `js/tone-registry.js`（HK.TONES）の一か所にまとまっている。名前・説明・一人称・選択欄の並び・
借りる文面の表・設定画面の見本・場面ごとの分類（敬語／やわらかい／強い）・渋りやすさは、すべてここから読む。

1. `tone-registry.js` の TONES に一つ足す（書く順が選択欄の並び）。
2. 既存の口調の台詞を作ってから語尾だけ替える口調なら `derive: 'polite'` のように派生元を書き、
   語尾の付け替えを `HK.toneFinish('口調', 関数)` で登録する（例：`tone-polite-kin.js` の後輩・お嬢様）。
   その口調名で `tone-fix.js` に登録した直しは、付け替えずにそのまま使われる。
3. まったく新しい言い換えが要る口調は、`tone-extra2.js` などと同じく `V.styleQuote` を包んで書く。
4. 両方のビルドに同じファイルを置く。ここの道具は `HK.TONE_KEYS` を読むので、新しい口調もそのまま点検される。

## 書き下ろし辞書の育て方

- 辞書は `js/voice-override.js`（古風な紳士・決まり文句の表）と `js/voice-override-rows.js`（のじゃ・関西弁・無口・敬語、
  敬語まじりのため口は同じファイルの MIXED）。
  両方のビルドに同じファイルを置く。
- 元の台詞の住人の名前は `〈〉` にして書く。一人称は「私」で書けば、その人の一人称にそろう。
- 優先するのは **出現回数が多い台詞 × 自動変換で元のまま残る台詞 × 元の口調から遠い口調**。
  上位200〜300行で、プレイヤーが目にする台詞の約半分になる。
- 書き足したら `collect.js` → `report.js` で、「元のまま」の割合が下がったかを確かめる。

## 新しく台詞を書くときの決まり

- 語尾は中立に（「〜だ」「〜ない」「〜した」）。「〜じゃん」「〜だよね」「〜わよ」のような口癖は、
  自動変換が外しきれないので、元の文にはなるべく入れない。
- 一人称は「私」、二人称は名前か「あなた」で書く。
- 長い台詞は、読点で区切った短い文の連なりにする（文末だけ変換されても読めるように）。

## orient-audit.js（恋愛対象の点検）

```
node orient-audit.js ../../hakoniwa-full 40 r18 --why
node orient-audit.js ../../hakoniwa-full 40 safe --why
node orient-audit.js ../../hakoniwa-zenrei 40 '' --why
```

恋愛対象（男性／女性／なし）に合わない相手と、恋人・夜・片想いの結末（O1）、二人だけの性的な場面（O2）、告白（O3）になっていないかを全箱庭で数える。O2・O3 は文から拾うので、--why の例を目で確かめる。受け攻めは pos-audit.js で見る。
