# 箱庭テキスト工房（文の閲覧・試し読み・編集・点検）

コードを直接開かずに、箱庭シミュレーターの文（台詞・地の文・喘ぎ・口調の辞書・イベント）を
ブラウザの画面で見て、その場で直したり、イベントを足したり、不整合を調べたりするための道具です。
外部のパッケージは要りません（Node.js だけ。構文解析の acorn は `vendor/` に同梱）。

## 起動

```sh
node hakoniwa-tools/text-studio/server.js
# → ブラウザで http://localhost:4580/ を開く
```

- フォルダを指定しなければ `hakoniwa-full` と `hakoniwa-zenrei` を読みます。別のフォルダ（`js/_order.txt` のあるビルド）は、
  `node server.js <フォルダ> <フォルダ>` で起動するか、画面の「＋フォルダ」で足せます。
- ポートは `--port 4590` で変えられます。localhost からしか使えません。

## しくみ

| 部品 | 役目 |
|---|---|
| `scan.js` | ビルドの js を構文解析し、文の「群」を拾う。群ごとにファイルの位置・パス（`D.V.proud.start` など）・候補を持つ |
| `check.js` | 書かれた文の点検（下の「点検」） |
| `server.js` | 画面と API。書き換えはファイルの該当する文字列だけを置き換え、構文を確かめてから保存する |
| `public/sandbox.js` | 試し実行用のページ（iframe）。ビルドの js を `_order.txt` の順に**個々に**読み込むので、ビルドしなくても直した文がすぐ反映される |
| `public/app.js` | 画面 |

群の種類：

- **配列** `['…', '…']` … 要素の一つ一つが候補
- **|区切り** `L('…|…')`・`E(…, '…|…')` … 区切りの一つ一つが候補
- **辞書** タブ区切りの行（`tone-fix*.js`・`voice-override-rows.js` など）… 一行が一つの候補で、列ごとに直せる
- **一文** 配列に入っていない一つだけの文（`text: '…'` など）。`'…' + a.name + '…'` のような式は〔〕でコードを見せ、コードのまま直す

## 画面

| タブ | できること |
|---|---|
| 概要 | 箱庭ごとのイベント数（共通・箱庭の・小イベント・ハプニング）・文の群・文の数・R18専用の文の数。「調べる」で何回か回して、実際に出た文の割合と、各イベントが起きた回数を出す |
| 箱庭の文 | 箱庭を選ぶと、その箱庭の文の群がずらっと並ぶ（その箱庭のファイルの群＋回して出てきた群）。よく出る順・出なかった文がある群・R18専用だけ、で並べ替え。上の「イベント」を開くと、出来事の一覧（場所・起きた回数）と「これを元に新しいイベント」 |
| 試し実行 | 箱庭・人数・名前・性別・口調・受け攻め・場面の設定・乱数の種を決めて一回回す（🎲でランダム）。記録の文をクリックすると、その文が書かれた場所が出て、そのまま直せる。「口調の言い換え前を見る」で元の文も見られる |
| 口調・態度 | 口調（31種）・態度（9種）と箱庭を選ぶと、3つの見方ができる。**この箱庭の台詞をこの口調で**：箱庭の「」の台詞をすべて（同じ台詞はまとめて）、その口調の人が話したときの出来上がりで並べ、出どころ（辞書の書き直し／ほかの書き下ろし辞書／自動の言い換え／変わらない）で絞れる。並べ方は「よく出る順」「長い順」「優先度順（出る回数×長さ）」「ファイル順」。「回して出る回数を数える」で箱庭を何回か回すと、実際に出た回数で並ぶ（回す前は、書かれている箇所の数）。右の欄を書き換えて「保存」すると、その口調の書き直しとして `tone-fix.js`（R18専用の箱庭の台詞は `tone-fix-r18.js`）に入る（名前は〈〉、一人称は「私」）。「消す」で自動の言い換えに戻す。**口調ごとの書き分け**：パスに口調・態度の名前がある群（その口調が借りる態度の表も）と、辞書のこの口調の行（箱庭を選べばその箱庭の台詞の行だけ）。**言い換えの見本**：一つの台詞を全口調×男女で |
| 口調別の表（喘ぎなど） | 口調・態度で分かれた表を、行＝口調・態度、列＝区分（start・mid・climax…）のマス目で見せる。数字は候補の数、9種のうち抜けている行・1つだけのマスは赤。マスをクリックで文を表示・編集 |
| 文をさがす | 全文検索（`/…/` で正規表現）。台詞・解説・画面の文、箱庭、R18専用で絞れる |
| 点検 | 書かれた文の点検と、全箱庭を試しに回す点検（止まる組み合わせ・ページのエラー・出なかった文の数） |
| 依頼と更新履歴 | 更新履歴（docs/CHANGELOG.md）のいちばん上の節の見出しを選んで箇条書きを足す。今日の節がなければ作れる。AIへの依頼の控えを見る・足す |

### 編集画面（文をクリックすると右に開く）

- 候補ごとに直して「保存」。|区切りや配列なら「消す」「候補を足す」もできる
- 見本の名前と話し手の口調を選ぶと、`{a}{b}` を名前にして、その口調で言い換えた文を下に出す。「全口調で見る」で全口調×男女の表
- 「コードで直す」… 群のコードをそのまま直す（式でつないだ文や、ほかの値もいっしょに直したいとき）
- 「AIに依頼」… 直してほしいことを書いて、`ai-requests.md` に控えを書き足すか、Claude Code に貼る指示をコピーする
- 「このイベントを元に新しいイベント」… 元のイベントのコードを下書きにして、id と文を書き換えて、すぐ後ろに足す

### 保存したとき

- 同じ名前のファイルがもう片方のビルドにあれば、同じ群を探して同じ場所も直す（直せなかったときは画面に出る。R18専用のファイルは片方だけ）
- 試し実行のページは自動で読み直される（ビルドしなくても試せる）
- **コミットの前に、上の「ビルド」を押す**（両方のビルドで `hakoniwa-tools/build/build.js` を実行し、`bundle-*.js` と index.html を作り直す）
- 文を足したり直したりしたら、「依頼と更新履歴」タブで更新履歴に一行足す（CLAUDE.md の決まり）
- js を変えたあとの確認（tone-check の collect.js・pos-audit.js）は、これまでどおり

## 点検（コマンドでも）

```sh
node hakoniwa-tools/text-studio/scan.js hakoniwa-full stats                     # 箱庭ごと・ファイルごとの群・文・イベントの定義の数
node hakoniwa-tools/text-studio/scan.js hakoniwa-full check hakoniwa-zenrei     # 点検（2つ目のフォルダは比べる相手）
node hakoniwa-tools/text-studio/scan.js hakoniwa-full groups                    # 群の一覧（ファイル:行・種類・候補の数・パス）
```

| 点検 | 重さ | 中身 |
|---|---|---|
| 空の候補 | error | `'…||…'` の途中の空、空の文 |
| 置き換え記号の崩れ | error | `{a` のように閉じていない置き換え記号 |
| 括弧の対応 | warn | 「」『』（）の数が合わない。`+` でつなぐ式の一部や、人狼の `J.open`／`J.close` のように切り出しと締めに分けた群（足りない向きが全部そろっている群）は除く |
| 同じ候補の重複 | warn | 8字以上の同じ候補・辞書の同じ行が二度ある |
| 句読点の重なり | warn | 。。・、、・「。 など（「。」のように記号そのものを括弧でくくった説明は除く） |
| 態度9種の表の抜け | warn | 値が文の候補で、態度のキーが5つ以上ある表で、そろっていないもの。敬語（polite）は、表になければ persona-final.js が健気（devoted）の行を借りて埋めるので数えない。`{ proud: 1 }` のような分類の表や、`addP(表, {…})` で足す分は除く |
| 候補が1つだけの段（R18） | info | R18専用ファイルで、候補が1つ・2文以下の群（R18の文の基準「1文だけで固定の段を作らない」） |
| 短い候補の重複（重みづけ？） | info | `['施術着', '施術着', …]` のような短い候補の重複（出やすさの重みづけのことが多い） |
| 最後が空の「\|」 | info | `'…|'`（何も足さない候補として書かれていることが多い） |
| 全年齢版と違う所 | info | 両方にある同名ファイルで、同じパスの台詞・地の文・解説が違う（`.r18`／`.safe` の書き分けと、画面の説明は除く） |

言い換えの表（正規表現の元の文字列を含む行や、`[…][k]` で口調ごとに引く表）は「言い換えの表（コード）」として分け、
文の一覧・点検の対象から外します（「文をさがす」で種類を「言い換えの表」にすると見られます）。

`{a}{b}` と `{x}{y}` が一つの群に混ざっているかどうかは、書かれた文だけでは正しいか分からないので、
「全箱庭を試しに回して点検」で、出来上がった文に `{…}`・`undefined`・`NaN`・空の「」が残っていないかを見ます（置き換え残り）。

## 文の突き合わせについて

試し実行・使われ方の数は、記録の文（口調の言い換え前）の中に、各候補のいちばん長い固定部分（`{a}` などを除いた部分）が
含まれるかで数えます。短い候補（8字未満）は「」や句点に挟まれているときだけ数えます。組み立ての途中で作られる文や、
ごく短い言い回しは見つからないことがあるので、数は目安です。口調の辞書（tone-fix など）は、どの箱庭にも当たるので
箱庭の数には入れず、「口調・態度」タブで見ます。

## AIへの依頼の控え（ai-requests.md）

画面の「AIに依頼」で書いた依頼は `hakoniwa-tools/text-studio/ai-requests.md` に `- [ ]` の行でたまります。
Claude Code に「ai-requests.md の未完了の依頼を片付けて」と頼むと、CLAUDE.md の決まりに従って直し、終わった行を `[x]` にします。
